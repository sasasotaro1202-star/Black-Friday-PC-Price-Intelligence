# Black Friday PC Price Intelligence

2026年ブラックフライデーのPC購入判断を、価格だけではなく、構成・在庫・過去セール・待機リスク・データ品質まで統合して自動更新する基盤です。

## 目的

このリポジトリの100点は性能100点ではありません。ブラックフライデー期間全体で、今このPCを買う価値がどれだけ高いかを評価します。対象は**ノートPCとデスクトップPCを同じ購入候補集合**として扱い、価格だけで片方を有利にするのではなく、GPU世代・VRAM・CPU・TGP（ノート）・冷却・電源・拡張性・構成・在庫・将来性を用途に応じて比較します。

評価軸は固定の5要素です。

- 性能: 40
- 価格・実質28万円への近さ: 20
- 過去セール根拠: 15
- 在庫・売り切れリスク: 15
- 購入タイミング: 10

予算判定は現金価格だけでなく、必須送料・必須費用と、確実に適用できる値引き/還元を分離して扱います。実質コストはおおむね28万円を中心に評価し、28〜28.5万円は小幅超過、28.5〜29万円は性能・在庫・特典が明確に優位な場合だけ許容、29万円超は強く不利、30万円以上は原則参考扱いです。不確実なポイント、抽選、条件付き特典、不要な周辺機器値引きは実質コストから自動控除しません。

さらに、未確認情報が高得点を生むのを防ぐため、構成不一致・検索補完・在庫不明・低信頼ソースにはスコア上限を設けています。購入候補には観測鮮度の上限も適用し、通常監視では60分、ブラックフライデー期間では30分を超えた現行価格を購入判断から除外します。

## 最重要の安全策
- 現金支払額、必須費用、確定特典、実質コスト、未確定特典を別フィールドで保持します。
- `BUY_NOW_NEAR_BUDGET` は実質28.5〜29万円帯に限定し、スコア・性能・在庫・構成一致の追加条件を要求します。
- デスクトップの確認済み特典は、①追加の現金値引き、②周辺機器・構成アップグレード価値、③保証/サポート価値に分離します。②と③は実質コストから控除せず、最大5点の価値ボーナスとして価格20点の中に含めます。
- 「X円OFF」は表示価格に既に反映済みの可能性があるため、クーポン/カート/決済時などの追加値引きと確認できた場合だけ実質コストから控除します。
- 35〜40万円級のデスクトップも監視対象から外しません。29万円超で確認済み周辺機器・構成特典が強い高性能デスクトップは `VALUE_WATCH` として値下げ監視対象に残しますが、購入許可にはしません。



### 1. 価格抽出を「最小の数字」から卒業

Webページには月額料金、通常価格、ポイント還元額、分割支払額など、商品価格ではない数字が多数あります。

現在は、JSON-LD/product price、product price meta、価格文脈をスコア化した本文抽出の順で候補化し、月額・分割・ポイント等を除外します。

### 2. 異常な激安価格をそのまま採用しない

前回価格や公開基準価格から大きく乖離した価格は、まず異常値として棄却します。

例えばRTX 5070級なのに9万円のような価格が取得された場合、独立した検索結果で裏付けが取れない限り現在価格にはしません。

これによって、価格抽出ミスでランキング1位が偽装されることを防ぎます。

### 3. 同じ商品ページの構成違いを分離

ROG Strix G16のように、1つのURLに複数構成が存在するページは、ページが同じでも構成が同じとは扱いません。

config/candidate_catalog.json にCPU/GPU/RAM/SSD/TGP等の構成を保持し、共有ページは原則として構成不明扱いにします。

### 4. 取得失敗と売り切れを完全分離

- HTTP error / timeout → 取得失敗
- 在庫切れ表記 → 売り切れ
- 在庫情報なし → unknown

取得できなかったから売り切れ、という誤判定はしません。

### 5. 参照価格を現在価格にしない

公式ページが取得不能な場合でも、確認済み公開価格を reference_price_jpy として残します。

ただし参照価格は購入判断用の現在価格ではありません。BUY_NOW判定の材料には使いません。

### 6. PITを明示

各観測には event_time、event_time_upper_bound、publication_time、available_at、retrieval_time、prediction_time を分けて保存します。

販売店内部の正確な値札変更時刻が分からない場合、event_timeは推測せずnullです。

available_at が prediction_time より後になるデータは検証でFAILにします。

## ブラックフライデー期間

2026年の公式各社日程が十分に確認できない間は、広域監視を2026-11-14 00:00 JST ～ 2026-12-04 23:59 JSTとします。

通常監視は15分間隔、期間中は上位候補を5分間隔で監視します。

GitHub ActionsのcronはUTC基準なので、5分監視ワークフローはUTCで広めに起動し、ジョブ内でJSTの開始・終了を厳密に判定します。

2025年の参考事例では、Amazonが11/21〜11/23先行、11/24〜12/1本番、Lenovoが11/14〜12/4というキャンペーンを実施していました。これは2026年の確定日程ではなく、監視窓を設計するための過去データです。

## シナリオ分析

各候補について10%、15%、20%、25%、30% OFFと28万円到達を自動計算します。

シナリオは確率ではありません。データが20件未満の段階で、この時間に下がる、この割引になる、といった規則を勝手に作らないようにしています。

## 100点の判定

- 95〜100: 目標価格を満たし、データ品質も十分なら即購入級
- 90〜94: かなり強い購入候補
- 80〜89: 強い監視候補
- 70〜79: 値下げ待ち
- 69以下: 28万円化条件が厳しい、またはデータ品質に制約あり

スコアは確率ではありません。

## ノートPCとデスクトップPCの統合

- ノートPC：GPU/TGP、CPU、冷却、画面、重量、RAM/SSD拡張性を評価。
- デスクトップPC：デスクトップGPU/VRAM、CPU、冷却、電源、拡張性、RAM/SSDを評価。
- 両者は同じ100点の購入優先度で比較します。
- デスクトップの代表候補はG TUNE等の公式販売ページを起点に監視し、ブラックフライデー中の値下げで28万円前後に到達する可能性も継続評価します。
- 動的発見候補は構成未確認のまま強く推奨せず、正式カタログ候補を優先します。

## 自動運用

GitHub Actionsだけで動作し、外部の有料APIを必須にしません。

通常監視は15分間隔、2026年ブラックフライデー監視窓では5分間隔です。スケジューラ自体は5分ごとに起動し、通常期間は15分ごとだけ本処理を通します。これにより「設定上5分」と「実際の実行」が食い違わないようにしています。

処理順序:

monitor → sanitize → report → timing → scenario → healthcheck → validate → commit/push

各派生JSONには元の current_latest.json の生成時刻とSHA256を保存し、healthcheckで完全一致を要求します。価格観測とランキングが別スナップショットから混ざった場合は公開を停止します。

monitorは候補カバレッジも記録します。処理対象数、未処理ID、処理率、取得成功率、価格確認率を data/current_latest.json に残し、容量上限で取りこぼした候補も追跡します。

データ書き込みワークフローは共通concurrency groupを使用し、新しい監視実行を優先する設定にしています。古い監視実行が長時間残っても、最新の価格情報が待たされ続けないようにします。さらにpush失敗時はorigin/mainへ同期して最大3回再試行します。

## 出力

- data/current_latest.json: 最新観測、処理カバレッジ、価格確認率
- data/change_events.jsonl: 価格・在庫等の変化イベント
- data/decision_rankings.json: 100点ランキング、購入リンク、元観測スナップショットSHA256
- data/scenario_analysis.json: 値下げシナリオ、元観測スナップショットSHA256
- data/timing_analysis.json: 価格変更時間帯分析、元観測スナップショットSHA256
- data/reports/latest.md: 読みやすい最新レポート。現金総額・確定現金特典・実質コスト・非現金価値・購入リンクを表示

購入判断不能な場合も、無理に順位を作らず VERIFY_NOW / UNACTIONABLE / reference_only として残します。

公開直前には、PITチェーン、価格フィールド一致、スコア算術、ランキング順、top_recommendation、BUY_NOW条件、取得統計の整合性を再検査します。1項目でも壊れていればデータ公開を停止します。
